# Cannae OS v0.2.0

This release turns the original doctrine corpus into a substantially more
executable control plane for human-led AI work.

## Highlights

- Mandatory role-aware document routing for Codex and Claude Code, including
  wave-level CoS and per-agent S3 receipts.
- A fail-closed mission lifecycle that opens waves, issues digest-bound context
  packs, records repository-scoped evidence, closes with AAR state, and routes
  bounded follow-on work.
- Mission-based model force assignment with registry, qualification,
  heterogeneous billet compilation, integrated preflight, and usage evidence.
- Repository-isolated artifact storage with transaction journals, leases,
  fencing, verification, contention handling, and recovery.
- Finite self-improvement campaigns with observable acceptance criteria,
  runtime verification receipts, baseline/candidate comparison, rollback,
  accepted-parent lineage, and mandatory skill adaptation.
- Signed verifier identity and execution evidence, pre-dispatch freshness
  challenges, computed independence domains, and transparency-state admission.
- Native GitHub Actions and GitLab CI OIDC/JWKS verifier adapters.
- Per-agent dispatch policies and leases with pre/post-tool checkpoints,
  interruption, revocation, explicit resume, and provider hook adapters.
- An identity-bound protected tool gateway with idempotent transactions,
  cancellation, terminal receipts, and fail-closed recovery.
- Reference protected-process and measured OCI/Linux execution providers,
  followed by provider-neutral production sandbox appraisal and external
  coordinator contracts.
- Exact GitHub release authorization that binds one USER decision to the
  repository, stable tag, full commit SHA, successful main CI run, tracked
  release-notes digest, short expiry, publication verification, and terminal
  receipt.

## Authority Boundary

AI agents still cannot authorize policy, risk acceptance, merge, push, or
release. Execution, campaign, verifier, gateway, process, sandbox, and
production records retain `release_authorized: false`.

Only a short-lived, single-use `GitHubReleaseAuthorization` created from an
explicit human USER decision may carry `release_authorized: true`, and only for
the exact GitHub release named in that artifact.

## Skills

The repository includes equivalent Controls Doctrine Operator skills for:

- Codex CLI under `codex-skills/controls-doctrine-operator`; and
- Claude Code under `.claude/skills/controls-doctrine-operator`.

`install-ai-cli-skills.sh` discovers supported CLI skill locations and installs
both variants.

## Validation

The pull-request and default-branch `Validate` workflow runs:

- JSON parsing and Markdown-link checks;
- English-only corpus enforcement;
- validator fixtures and all `run-*.js` fixture families;
- source-map coverage and linting;
- complete document-routing inventory coverage;
- JavaScript syntax checks; and
- whitespace validation.

## Prototype Limits

Cannae OS remains a prototype and research framework. It supplies contracts,
deterministic local validators, skills, and reference adapters. It does not
operate production identity infrastructure, protected key custody, TPM/TEE
attestation, hardened sandbox hosts, registry policy, distributed
coordination, storage-side fencing, side-path isolation, or multi-user
administration.

The reference controls reduce ambiguity and catch tested failure classes. They
do not make an LLM non-hallucinatory, prove that every provider claim is true,
or replace human judgment and platform security controls.
