# Native Training Producer History

## Purpose

Preserve original native evidence across consumer upgrades without making an
old method current for execution. This is a prerequisite for native uncertainty
reconciliation, not that ceremony, a qualification or a grant.

The method binds code, policy, schema and dependency-lock bytes, not just schema
or package versions. The first captured candidate producer is
`cab6d098a1229ede35dff4697994ac34f5ad7418`, with original 21-file digest
`64882bcfe0d2319850c4234c4c31a71b0342575fa063ee143cf4c5817e4b9f04`.
The later captured producer is
`bcb79dd9009e96d4ffd4acd5f449d218ba768846`, with its original 23-file digest
`41bbc4bf46433f528d5e1a51aa44f5b924320c62c186273065e47eb53ff58d32`.
The current method additionally binds the inspection module and both pinned
catalogs. Inspections distinguish `historical_cab6d09`, `historical_bcb79dd` and
`current`; historical recognition is never a fresh-execution fallback.
Unknown/hybrid tuples, changed file order or bytes and extra metadata fail.

## Current-Engine Historical Replay

For every supported result, the current engine checks preview integrity,
prompt/schema, signed registry history, exact manifest prefix, handling review
and the signed result's original authorization/consent/invocation bindings.
For a `held` failure, `result_verified` describes those checks only. It does not
prove original-process termination, replay the raw journal or task bytes, or
discharge the hold.

Only the `collected` branch additionally reloads the original reservation,
terminal journal, JSONL, response and task bytes, checks their appraisal against
the signed result, and verifies canonical authorization/output/result publication.
Its historical profile comparison preserves only the recognized original harness
digest; model, prompt, tool schema/policy and execution commitments still match.
This is not independent publication finality, a grade or an operational grant.

The historical tuple supports reviewed owner previews v0.2 only; it cannot
upgrade an old purpose. Original records and signatures are never rewritten.

Fresh profile/invocation checks remain current-only. Publication rechecks current
scope and refuses old invocations. A known producer cannot excuse substituted
evidence or renew consent. Held native failures remain held, and the existing
omission/analysis reconciliation endpoints still refuse the native purpose.
Production never loads or executes archived source.

## Actual Prior-Producer Regression

The pinned JSON/catalogs and compressed source fixtures preserve each complete
prior tree, original commit object, method-file digests, source-state digest and
archive SHA-256. Snapshot v0.2 keeps previous source archives as flat external
blobs with exact path, size and SHA-256, rather than recursively embedding them.
Both versions remain readable. The test verifies all archive/blob buffers before
extraction, hydrates external blobs without overwrites, reconstructs the exact
Git identity and compares the original source digest. A missing, changed or
unsafe blob fails; a partial source tree is never accepted as the original.
Only this fixture
executes the frozen prior code, using synthetic owners and a measured fake
process to produce actual signed failures and collected products.

The owner API then restarts under today's engine against that same original
state. History must remain readable without rewriting the original row or
clearing a hold. Native-event tampering and old-method fresh execution/publication
still fail. Relabeling a new producer's record as legacy is not this test.

Keep an actual ignored `node_modules/` directory when restoring the fixture.
A top-level symlink is an untracked source change; preserve the original shape
rather than loosening the expected digest or ignore rules. Installed same-lock
dependencies are shared, not independently byte-attested or sandboxed.

## Remaining Work

Freeze a producer and generate its actual signed attempts before editing its
method-bound files. Source fixtures must contain source only, never runtime
authentication databases, private keys or exported credentials.

A failed assessment can throw before the original collector records
`response_sha256`, even when the signed journal binds the raw native JSONL and
the process exit. A response-file hash observed after that failure cannot be
presented as an original byte commitment. The dedicated
[native failure appraiser and owner consumer](native-training-failure-reconciliation.md)
distinguish those observations and inspect original final-event evidence,
process absence and exact publication prefixes. The generic held-row verifier
alone still does not supply that private-evidence appraisal or acknowledgment.

New producer tuples require a reviewed exact compatibility change and adversarial
replay. This catalog is not a human trust decision, quorum admission or execution
attestation. Appraisable failures now have a native-only fresh owner ceremony,
durable one-use receipt consumer and UI; genuine prior-producer fixtures exercise
that path while preserving the original failure and publications. This is not
real-human acceptance or a substitute for fresh consent to any later transfer.
Missing original evidence, unknown processes and orphans retain separate holds.
Grading, qualification, live grants, actual-model acceptance,
controlled rollout and all eight full program outcomes remain open.

This is local engineering synthesis of the existing
[producer compatibility pattern](github-release-independent-verification.md#producer-compatibility)
and [native owner contract](native-training-owner-consent.md), not new military
or provider-attestation claims.
