# Native Training Producer History

## Purpose

Preserve original native evidence across consumer upgrades without making an
old method current for execution. This is a prerequisite for native uncertainty
reconciliation, not that ceremony, a qualification or a grant.

The method binds code, policy, schema and dependency-lock bytes, not just schema
or package versions. The captured candidate producer is
`cab6d098a1229ede35dff4697994ac34f5ad7418`, with original 21-file digest
`64882bcfe0d2319850c4234c4c31a71b0342575fa063ee143cf4c5817e4b9f04`.
The current method additionally binds the inspection module and pinned catalog.
Unknown/hybrid tuples, changed file order or bytes and extra metadata fail.

## Current-Engine Historical Replay

The current engine rechecks preview integrity, prompt/schema, signed registry
history, exact manifest prefix, handling review, original consent/authorization,
reservation, terminal journal, JSONL, response and actual output. The historical
tuple supports reviewed owner previews v0.2 only; it cannot upgrade an old purpose.
Historical profile comparison preserves only its recognized original harness
digest; model, prompt, tool schema/policy and execution commitments still match.
Original records and signatures are never rewritten.

Fresh profile/invocation checks remain current-only. Publication rechecks current
scope and refuses old invocations. A known producer cannot excuse substituted
evidence or renew consent. Held native failures remain held, and the existing
omission/analysis reconciliation endpoints still refuse the native purpose.
Production never loads or executes archived source.

## Actual Prior-Producer Regression

The pinned JSON/catalog and compressed source fixture preserve the complete
prior tree, original commit object, method-file digests, source-state digest and
archive SHA-256. The test verifies the hash before extraction, reconstructs the
exact Git identity and compares the original source digest. Only this fixture
executes the frozen prior code, using synthetic owners and a measured fake
process to produce actual signed failures and collected products.

The owner API then restarts under today's engine against that same original
state. History must remain readable without rewriting the original row or
clearing a hold. Native-event tampering and old-method fresh execution/publication
still fail. Relabeling a new producer's record as legacy is not this test.

Keep an actual ignored `node_modules/` directory when restoring the fixture.
A top-level symlink is an untracked source change; preserve the original shape
rather than loosening the expected digest or ignore rules. Installed same-lock
dependencies are shared, not independently byte-attested or sandboxed.

## Remaining Work

New producer tuples require a reviewed exact compatibility change and adversarial
replay. This catalog is not a human trust decision, quorum admission or execution
attestation. Native uncertainty discharge still needs fresh authenticated human
review, original-process proof, partial-publication appraisal and a durable
one-use receipt. Missing original evidence, unknown processes and orphans retain
separate holds. Grading, qualification, live grants, actual-model acceptance,
controlled rollout and all eight full program outcomes remain open.

This is local engineering synthesis of the existing
[producer compatibility pattern](github-release-independent-verification.md#producer-compatibility)
and [native owner contract](native-training-owner-consent.md), not new military
or provider-attestation claims.
