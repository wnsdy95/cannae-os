# Native Training Task Products

## In-Progress Scope

This candidate adds the native-task standard and a purpose-separated actual
bounded collector API. It is not an operational owner-transfer product: the
new authenticated console ceremony/producer is not implemented. The installed
service must not be used to sign an unrelated purpose, and there is no signing
or execution CLI. All eight complete program outcomes remain open.
The context reference constrains the selected case/alias and mission fences; it
does not dispatch an operational delegated agent or adopt that agent's tools.
Complete actual intent/delegation consumers remain required under goal 1.

`TaskTrainingStandard` v0.1 remains the tool-hook reference path. Its v0.2 cases
name a native text task with explicit input, conditions and minimum byte count.
Both still require distinct crawl/walk cases and critical steps. A native
standard needs a separately owner-enrolled capability revision; do not rewrite
old standards or relabel a completed local read as an LLM task.

## Preparation And Execution Boundary

1. Prepare actual CLI profile metadata through the trusted host, preserving the
   existing login and separately frozen CLI-default selection. The profile API
   reads version/executable metadata; it is not inference or owner consent.
   Enroll the exact model, harness, template, empty-tool schema, tool policy and
   execution-profile commitments as an unassessed performer. The declared model
   revision/principal are not independently attested by that comparison.
2. Propose a `NativeTrainingProductRequest` with a fresh collection UUID, current
   registry head, exact capability/performer/context/case, classification and
   finite expiry. Use `native-training-product-cli.js propose` or either skill's
   `scripts/prepare_controls_training_product.js`. A proposal grants nothing.
3. The trusted API prepares the full original subject and exact prompt/profile.
   It checks enrolled definitions, native method, context/plan alias, `valid_until`,
   stop/termination, source/manifest and OPSEC. The future owner ceremony must
   personally approve this exact complete transfer under its own purpose.
   Current omission, analysis, definition and session consent cannot substitute.
   Transfer OPSEC/EEFI checks cover the exact selected-case prompt, not unused
   cases from the complete owner review. Unused cases are excluded from the
   explicit prompt; full native context remains unattested. Forbidden selected
   content still blocks. This baseline is not a universal
   release review or complete mission-specific sensitive-output policy.
4. Only a separately signed `TrainingProductTransferConsent` with purpose
   `one_native_training_product_transfer` can enter the collector. It reserves
   the collection UUID durably before starting a process, independently of the
   one-use consent ID. A second consent cannot relabel/reexecute that collection.
   Failed/partial reservations are not automatically cleared or retried.
5. The actual child uses the existing bounded single-turn, read-only, tool-denied
   CLI profile. The collector checks current scope before/after execution and
   during a one-second observation loop; drift cancels the child. It keeps a
   bounded owner-private original JSONL stream and requires one valid native
   thread before one observed turn, no tool events, an unchanged workspace,
   original final-response agreement and actual process/group termination.
6. `readProduct` reloads the original invocation, consent, reservation, terminal
   journal, JSONL and response bytes. It replays the original manifest prefix,
   recomputes event order and output commitments, and returns separate task bytes
   plus a non-executable appraisal. New later request history does not rewrite
   the earlier subject. Missing/tampered/symlinked evidence cannot become a result.

The preauthorized collection identity is not the provider thread identity.
`codex exec` receives its prompt before streaming startup notifications, so an
observed event order is not a gate proving upstream inference waited for identity
enrollment. Native account, model weights, protected host and pre-inference native
identity remain unattested. The local private journal is trusted-host evidence,
not an independently signed execution attestation.

## Evidence And Remaining Work

Transport objects, requests, profiles, collections and appraisals remain control
metadata, not deliverables. The raw task bytes are distinct. OPSEC/EEFI findings
keep returned content quarantined in the owner-private collector state; this
candidate supplies no public output/release path. Existing sensitive-output,
classification and revocation requirements still apply to any later publication.

Run `run-native-training-product-contract-fixtures.js` and
`run-native-training-product-fixtures.js`. Their executable is a measured fake
provider and their owners are synthetic. They prove local control behavior,
not real-account inference, task quality, calibrated semantics or qualification.

Complete the purpose-specific owner UI and signed result publication, complete
all-attempt/failure inventory and uncertain-outcome recovery, authenticated step
evaluation, separate USER qualification, P supervision and mandatory real grant
consumers. Current-source full acceptance, stacked main integration and controlled
rollout remain separate. No real owner, credential export, model call or installed
service upgrade is part of these fixtures.
