# Native Training Owner Consent

## Candidate Boundary

This in-progress local candidate connects the authenticated owner console to
the native task-product collector, original task bytes and signed publication.
It advances goals 3/5/7, not completion of any of the eight program outcomes.
Current-source acceptance, actual approved model runs and controlled rollout
remain required. Existing installed skills and the running service are unchanged.

## Exact Handling Review

Propose a `NativeTrainingProductRequest` first. Then propose one
`NativeTrainingTransferReviewRequest` with the exact manifest reference and prompt
hash, USER-authored labels for both the request and standard, the mission handling
inventory, per-artifact releasability review and `ReleaseReview` targeting
`external_tool`. Both skill wrappers support the non-authorizing `propose-review`
command. Construct a new content-derived ID for changed input; never reuse an ID.

The runtime validates the existing label/releasability/release schemas, exact
mission/request/digest/prompt, reviewer, target, delivery mode and finite windows.
Sensitive/restricted, transfer/output-forbidden, internal-only or expired labels
deny. Stronger retained source labels cannot be omitted by an inline proposal.
For shared standards this includes the exact original source mission and label
references, not only labels in the receiving mission. Retargeting the host's
pinned physical artifact root also denies; equivalent path aliases do not grant
access to a different root.
Internal labels must explicitly permit the original context's receiving role.
After these checks, the existing context filter and release evaluator must agree
on raw delivery to `external_tool`; schema-valid review text alone is insufficient.
Default detectors and bounded literal mission terms inspect the actual outbound
prompt. They do not prove the semantic completeness of a human-authored inventory.
The owner acknowledges that inventory explicitly; independent completeness remains
false. This is an authenticated human judgment, not a model's clearance claim.

The trusted host configures the training executable and model separately with
`--training-executable` and `--training-model`. `@cli-default` uses the existing
host preparation path and freezes a concrete selection before display. It is not
sent as a literal provider model. No key is created/exported and no real login,
setup, configuration, installation or inference is performed by the fixtures.

## Actual Owner Ceremony

From the exact request in Evidence, select **Review Training Transfer**. The
console displays the full invocation, exact prompt/profile, complete handling
review and original source labels. Both displayed digests and handling text are
checked again at submission. Owner session/epoch, password, CSRF/origin and one-use
nonce are required, along with the separate mission-handling acknowledgment.
The old omission, analysis, definition or session endpoint cannot approve it.

The console atomically reserves the action, signs the exact transfer consent and
`NativeTrainingTransferAuthorization`, and retains both before process startup.
The original reviewed v0.2 subject is reconstructed using the trusted registry
key. Legacy v0.1 collection previews cannot enter this owner path. Changing the
source, manifest, registry, case, profile, stop state, expiry or owner session
fences execution/publication; actual stop/logout/shutdown cancels the child.

## Original Evidence And Uncertainty

The [producer-history foundation](native-training-producer-history.md) preserves
exact original owner evidence across a method-hash upgrade using current-engine
replay. Known historical metadata cannot authorize a fresh transfer, qualify a
performer or discharge a held attempt; unknown/hybrid producers remain denied.

Before publication, independently reload original consent, reservation, terminal
journal, JSONL, response and task bytes. Mission-specific output findings retain
owner-private quarantine. A guarded sequence publishes the signed authorization,
original bytes and signed `OperatorNativeTrainingProduct`. Each owned write
advances the expected manifest; current source/auth/scope checks still apply.
The signed appraisal and wrappers are metadata, not work. The separately retained
text is the actual candidate task product.
The shared file-store API must verify `expectedSha256` against its actual write
buffer before publication; a substituted staged file must not leave a canonical
output artifact. See [repository isolation](repository-artifact-isolation-policy.md).

**Model Actions** retains every managed native action, including pending,
invalidated, running, collected, failed/held and unverifiable states. Native
reservation/authorization orphans are enumerated and block new model transfers.
A reservation must match original signed consent and authorization, request,
invocation and pre-start timestamps; a matching unsigned pending preview is not
enough to classify it as an authorized attempt.
Read-only publication inspection also lists exact deterministic artifacts after
partial or acknowledgment-lost writes. A missing database result or changed
original evidence cannot become an accepted collected row. Canonical candidate
records alone are not independent publication finality or a grade.

Partial writes, restart, unknown exit or lost acknowledgment stay held. Native
uncertainty discharge is not implemented; omission/analysis reconciliation must
refuse it. Never delete reservations, rewrite earlier failures, regenerate a
missing signed record or rerun a task to clear a hold. Future reconciliation must
bind exact original evidence and a fresh, separately authenticated USER decision.
