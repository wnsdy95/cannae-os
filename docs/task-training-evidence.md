# Task Training Evidence

## Work In Progress

Goal 5 requires actual training observations, an authenticated task qualification,
and new bounded operational grants that consume it. These are distinct decisions.
This in-progress implementation supplies the evidence intake foundation. It does
not finish qualification or the grant consumer. All eight full outcomes stay open.

The intended full sequence is:

```text
reviewed standard + stable capability/performer definitions
-> owner-authorized session mapping before the trial
-> bounded real execution and retained result
-> authenticated step evaluation and USER qualification
-> a separately approved new grant
-> repeated freshness/configuration checks at actual next-call/gateway consumers
```

The Army's 2026 training-management explanation distinguishes observations
against task standards from the commander's broader proficiency assessment.
Assessment then informs further training. This supports separating observations
from a qualification decision; it supplies no automatic LLM grade or permission.
[Army Training Management Directorate, June 26, 2026](https://www.army.mil/article-amp/293526/met_assessment_initiates_the_training_management_cycle).

## Current Intake Contract

`TaskTrainingStandard` records a capability/METL/task identity, explicit conditions,
critical steps, required task-product/boundary evidence, permitted N/A, distinct
crawl/walk cases, a validity window and sustainment interval. Critical steps may
not be marked N/A. The local three-trial floor is project policy, not a numerical
Army requirement. Enroll its exact bytes as the capability's standard through
the existing owner-reviewed force registry; enrollment is still not qualification.

`TaskTrainingSessionBinding` links a stable performer/version and declared
configuration to one actual lease and provider session. The operator public key
must be pinned independently of incoming records. A session ID is not a stable
principal and never replaces the performer's identity. The mapping must already
exist before the counted admission, with the same enrolled capability/performer
versions. A late label or a post-hoc signed mapping cannot make an earlier call a
valid training trial.
The mapping fixes the training stage and allowed case IDs before execution;
the caller cannot relabel an earlier crawl call as a walk trial. The appraisal
returns a deterministic review deadline, not a cached claim of current freshness.

**The real owner session-binding ceremony is not implemented yet.** Current
fixtures explicitly construct synthetic signed bindings in an isolated synthetic
operator store. Those tests do not prove a real owner approval path. There is no
public signing/approve CLI, real-owner automation, key import, or active-service
upgrade in this slice.

`TaskTrainingCompletionInput` retains the precise result-digest projection used
by actual dispatch completion. `TaskTrainingTrialRequest` names that input,
the actual lease/post-tool checkpoint, case, session mapping and retained output.
The appraiser verifies immutable registry history, pre-call enrollment, exact
role/task alias, provider/session, same-mission/wave result references, actual
allow admission, case input hash, checkpoint lineage, terminal lease and absent
pending/unknown tool/gateway obligations. It recomputes the provider-result digest
using the dispatch implementation and compares exact UTF-8 output bytes. It does
not execute a submitted command or accept a caller's success claim.

Case input commitments use the dispatcher's exported `inputDigest`, including
its canonical final newline, rather than the artifact digest domain. A producer
regression and an actual admitted-call fixture exercise that boundary; matching
schemas and synthetic samples alone do not. An incorrectly enrolled live standard
requires a fresh owner-reviewed revision, not rewritten history or dual-hash
acceptance. Only the synthetic examples are regenerated by the fixture writer.

`TaskTrainingTrialAppraisal` returns `observed_result_bound`. That means the
retained result matches a covered call, not that the task was performed well.
Settled failed trials must remain visible; a failed execution is not a GO. This
record, the standard, mapping and completion input are control metadata, not task
deliverables. Training artifacts are owner-only even for a mission-bounded viewer.

Conditions, actual model identity/configuration, evaluator competence, task
quality and positive qualification remain unproven. The appraisal keeps their
flags false. Declared model/prompt/harness/tool hashes and a signed session mapping
do not attest provider weights or a protected host. Empty output is acceptable
only when the reviewed case explicitly permits its byte count; it is not a task
product quality guarantee.

The actual-dispatch fixtures use only isolated synthetic accounts and perform a

installed owner, daemon or credentials. Preserve early routing/validation failure
records; an unexecuted test suffix is not a pass.

Next, implement the actual purpose-bound owner session ceremony, complete
trial/failure inventory and independently authenticated step evaluations. Require
all critical observations, explicit applicability, current configuration, distinct
stage evidence, retained incidents and prior-stage qualification. No missing
observation may become GO, and a critical failure cannot disappear into an average.
Then implement exact owner qualification, bounded P supervision and mandatory
stable assignments across plans/contexts/model policies/leases/gateway consumers.
Reconcile old agents, model/resource/approval/delegation scopes and unsettled
effects before fresh restoration. Never resurrect an old lease or clear a drop
through a promotion label, new mission or renamed task.

Full organization lifecycle, CoS/COP integration, accepted rollout and externally
protected deployment remain required. This foundation is neither calibrated
semantic evaluation nor complete training/readiness automation.
