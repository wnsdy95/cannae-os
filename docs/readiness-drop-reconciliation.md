# Readiness Drop And Existing Grants

## Boundary

This local candidate connects retained `READINESS_EVENT` observations to actual
dispatch issuance, next-call admission, completion and gateway admission/begin
checks. It is a restrictive fence, not positive readiness qualification or a
complete cross-mission capability registry. All eight program outcomes remain
open; implementation, source acceptance and installed rollout are separate.

An actual synthetic probe on `c475726` stored a schema-valid T-to-X event for the
same role and exact task after one completed call. The next real dispatcher
admission still returned allow. The target archive and source-bound observation
are retained separately; this is a missing consumer, not a protected-host bypass
or real model experiment.

## Matching And History

Read the verified repository artifact namespace, including other missions, for
kind `readiness-events`. Bind every event to its manifest identity and originating
mission. Validate its full existing contract, EVALUATOR actor, UTF-8, digest and
bounded regular path. Effective and introduction timestamps use parsed instants,
not string sorting; future observations and backdated transition conflicts hold.
Current manifests sort paths, not event chronology. Multiple observations replay
their actual introduction revisions from retained manifest history, then verify
the previous/new rating chain. Conflicting METL identities for the same exact
role/task hold rather than selecting one arbitrarily.

The current receiver match is **exact operational role and exact task bytes**.
It cannot recognize renamed/paraphrased work, stable performer identity, changed
model/tool qualification or equivalent capabilities. A different role/task is
not narrowed by this observation. Stable capability/METL/performer bindings are
still required to close goal 5; do not present literal matching as that registry.

## Restriction And Settlement

A retained demotion or U/X observation fences the old role/task scope. No later
promotion, generic approval, new mission, resumed session or expiry silently
restores that grant. A missing drop is not proof of qualification: this candidate
does not certify T/P or repair the remaining positive-admission gap.

- Lease preparation, resumed/frozen issuance recovery and publication recheck the
  current fence. A record arriving during publication cannot renew authority.
- Actual next-call admission denies `READINESS_REQUALIFICATION_REQUIRED` and
  records revocation. If a tool, unknown effect or gateway obligation remains,
  the existing transition produces blocked instead of pretending it is settled.
- The actual gateway rechecks the same active-lease guard before authorization,
  begin and publication. A previously authorized transaction cannot start after
  the drop. Its ownership and recovery duties remain; denial is not cancellation.
- Already admitted results, exact cancellation and existing effect settlement
  remain available. Collect and reconcile them without rerunning the tool. A
  successful late result does not restore authority or make the wave complete.
- After settlement, run reconciliation again to record terminal revocation.
  Completion cannot bypass the fence by labeling a demoted agent successful.

The restrictive history is immutable. There is deliberately no clear, promote,
restore or clock-override command. A separate USER-approved requalification and
new grant protocol is still needed; do not delete or rewrite an event to proceed.

## Operator Procedure

Use the actual target repository and the same artifact root as its mission.
Claude has the equivalent wrapper under `.claude/skills/`.

```bash
node codex-skills/controls-doctrine-operator/scripts/reconcile_controls_readiness.js \
  inspect --repository <target-repository> --artifact-root <artifact-root>

node codex-skills/controls-doctrine-operator/scripts/reconcile_controls_readiness.js \
  reconcile --repository <target-repository> --artifact-root <artifact-root>
```

Inspection is read-only. Reconciliation only narrows existing leases and appends
a digest-bound `ReadinessDropReconciliation` with exact event/checkpoint refs.
Blocked and revoked are distinct results. An interrupted batch can already have
published some checkpoints; inspect before retrying. Reports are control metadata,
not task work, full reconciliation completeness, approval revocation proof,
training evidence or execution/release authority. Source records and reports
both validate with `can_execute: false`.

## Verification And Remaining Work

Run `node run-readiness-drop-revocation-fixtures.js`, the generic validator,
dispatch/gateway/issuance/metadata fixtures and both-provider skill/routing checks
from one frozen source. Preserve the original allow-after-drop observation.
Tests distinguish actual next-call and pending-result integration from direct
history-reader payload rejection; a random denial does not prove a specific rule.
Regress actual publication races and path/time ordering, not only schemas.

Remaining: stable cross-mission capability ownership and performer/model/tool
identity; authenticated evaluator provenance and USER requalification; complete
crawl/walk/run evidence and freshness; P-stage supervision and new positive
admission; approval scopes and standing delegations; automatic reassignment;
broader operational COP/CoS reporting; accepted installation and protected
deployment. A retained EVALUATOR field is not cryptographic identity, and a
local trusted artifact store is not an independently protected host or key.
