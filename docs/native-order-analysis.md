# Native Request Analysis And Proposed Orders

## Boundary

This local candidate lets the selected existing Codex CLI propose a typed mission
analysis from one retained request and compiles its result through the actual
request-to-OPORD compiler. It does not make an omission evaluator a planner, grant
task tools, calibrate semantics, adopt an order or close any program outcome.
The structural plan generator still uses an explicit roster/policy/control
envelope; a proposed analysis cannot invent capacity or reset parent budgets.

The shared bounded collector preserves the pinned CLI 0.162.1 transport, finite
process/output limits, private one-use journal, no automatic retry and observed
child/group exit. Purpose adapters fix the preview, prompt, schema, invocation,
consent and result types in trusted code. An omission consent cannot execute an
analysis invocation, nor can an analysis challenge be committed at the omission
endpoint. Saved login and prior order consent never authorize this transmission.
This is local process control, not protected-host or native-context attestation.

## Prepare And Review

Capture the exact request with the existing compiler first. Both provider skills
offer a prepare-only wrapper; it requires the target repository and exposes no
run, model, role, approval or clock override:

```bash
node codex-skills/controls-doctrine-operator/scripts/prepare_controls_analysis.js \
  prepare --repository <repository> --request-id <retained-request-id> \
  --artifact-root <artifact-root>
```

Preparation verifies current source, request, manifest, handling, OPSEC/EEFI and
a finite proposed-role envelope. Only public/internal request text is transmitted;
there are no evidence-file or arbitrary source-ref inputs. The preview binds
exact source, schema, method, roles and runtime state and expires within five
minutes. It transmits nothing. Default proposed roles are S2/S3; a trusted library
host may configure a finite subset of the known non-command roles.

The trusted host separately configures `--analysis-executable` and
`--analysis-model`; neither comes from a browser body or request instructions.
Open the retained mission request in Evidence and select Propose Order Analysis.
Review the complete packet, model alias, CLI/executable digest, purpose, role
envelope, limits and absence of a provider billing cap. The authenticated owner
reauthenticates with a password and one-use session-bound nonce for purpose
`one_order_analysis_transfer_and_draft`. Never automate real owner approval,
create a development signing key for real work or expose private packet content
in agent chat. The distinct omission profile remains independently opt-in.

## Actual Output Consumption

Model responses contain only statements, section references, role tasks, retained
decisions and false authority flags. Mission/wave/request identities and analysis
ID are bound by the host. Source quotes must match exact UTF-8 bytes; unsupported
facts, duplicate/missing references, unknown fields, authority fields and roles
outside the reviewed envelope fail. Proposals, assumptions and unknowns remain
explicitly separate from attributed facts.

The actual compiler verifies the source again and persists a non-executable draft.
Blocking unknowns or incomplete required sections produce needs_clarification,
never a manufactured ready result. Successful analysis still needs independently
reviewed human inventory/coverage, complete bounded plan review, USER adoption,
backbrief/rehearsal, model/routing preflight and actual dispatch gates.

The signed `OperatorOrderAnalysis` binds response digest, original collector
journal and compiled draft reference/status. It is control metadata, including
nested/wrapped copies, not work evidence. The draft does not prove complete
extraction or good strategy. It does not yet carry a calibrated model-origin
admission class; actual adoption remains the separate human-review class.

Inspect Model Actions after lost delivery. Failed, unknown, changed-source or
interrupted collection/publication remains held and fences both local model
purposes. The existing omission-only failed-transfer acknowledgment explicitly
rejects analysis actions; a purpose-specific analysis recovery ceremony remains
unfinished. Never delete rows, relabel purpose, reuse a nonce or rerun a model to
clear a hold. Result inspection cannot establish remote cancellation or billing.
