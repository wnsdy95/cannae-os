# Native Order Analysis Fixtures

These fixtures use measured fake CLI processes and synthetic owners, never real
credentials or model-quality evidence. Run `run-order-analysis-generation-fixtures.js`
for strict response/source/purpose, real compiler/structural-plan and wrapper
consumers. Run `run-native-order-analysis-fixtures.js` for actual authenticated
HTTP collection, compiled draft/journal/result bindings, purpose separation,
clarification, viewer denial, logout and shared failure holds. Existing omission
and reconciliation suites still own their legacy contracts.

`run-operator-analysis-reconciliation-contract-fixtures.js` checks distinct
purpose/signature/publication bindings and unchanged omission compatibility.
`run-operator-analysis-reconciliation-fixtures.js` exercises the actual owner
API, before/after compiler publication, two acknowledgments, purpose swapping,
drift, persistence failure, restart and process death at both receipt boundaries.
`reconciliation-browser-check.js --output <dir>` covers real synthetic browser
desktop/mobile, malformed previews, lost response and delayed owner-to-viewer
clearing. Focused exported development cases never count as full-suite proof.
See [the exact procedure](../docs/order-analysis-reconciliation.md).

Regenerate only response/result schemas and authored examples with
`node order-analysis-fixtures/write-schemas-and-samples.js`. Do not rewrite old
private collector evidence or treat these authored cases as independent labels.
Use `write-reconciliation-samples.js` only for the new synthetic analysis contract
schemas/examples/public key. Preserve existing omission examples and actual
retained journals byte-for-byte; no private fixture key is saved by either writer.
